6. [CCRM-176][lld] 链接器默认启用未引用节垃圾回收(GC) .............. PASS
   ------------------------------------------------------------------
   测试源: src\gc_default.c (used_func/used_global 被 _start 引用;
           unused_func/unused_global 不被引用)
   命令:
     clang ... gc_default.o -nostdlib -T gc_default.ld   -> 链接
   a) 经 clang 驱动链接(默认): 用 llvm-nm 检查最终 ELF
      -> 仅保留 _start, used_func, used_global；unused_func/unused_global 被回收
      -> -### 确认驱动默认传递 "--gc-sections"
   b) 直接调用 ld.lld 且不带 --gc-sections: 两个未引用符号均保留(无 GC)
   c) 直接调用 ld.lld 带 --gc-sections: 与 a) 相同，均被回收
   结论: GC 默认开启经由 clang 驱动实现(默认传 --gc-sections)。PASS

7. [CCRM-110][clang] 新增 -Wsection-feature 警告选项 ............... PASS
   ------------------------------------------------------------------
   测试源: src\section_feature.c (按 userguide 示例) /
           src\section_feature_min.c
   a) -Wsection-feature 编译: 产生 4 条警告，例如
      warning: .test11 uses more than one section feature [-Wsection-feature]
      warning: '#pragma clang section' overrides previous active section
   b) -Wno-section-feature: 无警告(可抑制)
   c) 默认(不带选项): 无警告(默认关闭，需显式开启)
   实测附加行为: 由于 -ffunction-sections/-fdata-sections 默认开启，单独的
      __attribute__((section)) 也会被判定为 "超过一个 section 特性" 而告警
      (即使 -fno-function-sections -fno-data-sections 亦如此)。
   结论: 选项存在且按 userguide 行为触发/抑制警告。PASS
