[CCRM-176] Emit functions and static allocated variables into unique sections by default

11.0.0 中 -ffunction-sections / -fdata-sections（以及 -fpragma-function-sections / -fpragma-data-sections）默认使能，函数与静态分配变量默认生成独立节。不使用任何 -ffunction-sections/-fdata-sections 选项直接编译，检查目标文件节名：

// sections_default.c / rodata_test.c（默认编译）
llvm-objdump -h sections_default.o  ->
    .text.func_a    .text.func_b    .text.helper        (函数)
    .data.global_init .data.static_init                 (已初始化数据)
    .bss.global_zero .bss.static_zero                   (零初始化数据)
    .rodata.table   .rodata.msg                         (常量数据)

通过 clang -### 确认驱动默认传递 -ffunction-sections -fdata-sections -fpragma-function-sections -fpragma-data-sections。

注意事项：默认独立节会改变输出段的组织方式，用户工程链接脚本需包含 *(.text*)、*(.data*)、*(.bss*) 等带通配符的匹配规则，否则内容可能被遗漏。对自定义段（#pragma clang section）导致的问题，可通过 -fno-pragma-function-sections -fno-pragma-data-sections 关闭，迁移方法参考 HighTec 移植指南（与 TriCore-llvm v11.0.0 一致）。

测试结果：通过。

[CCRM-176] Garbage collection of unreferenced sections by the linker is enabled by default

11.0.0 中链接器默认开启未引用节回收（经 clang 驱动默认传递 --gc-sections）。通过独立未使用的函数/变量验证：

// gc_default.c
int used_global = 42;    int unused_global = 99;   // unused_global 不被引用
int used_func(int x){ return x + used_global; }
int unused_func(int x){ return x * unused_global; } // unused_func 不被引用
void _start(void){ (void)used_func(1); for(;;); }

经 clang 驱动默认链接后，用 llvm-nm 检查最终 ELF：

clang ... -nostdlib -T gc_default.ld gc_default.o -o gc_default_clang.elf
llvm-nm gc_default_clang.elf  ->  仅 _start / used_func / used_global
                                   unused_func / unused_global 被回收
（-### 确认驱动默认传 --gc-sections）

对照：直接调用 ld.lld 且不带 --gc-sections 时未引用符号保留（符合 lld 原生语义）；显式 --gc-sections 时回收，与 clang 驱动默认行为一致。

测试结果：通过。

[CCRM-110] Add option -Wsection-feature to warn when a function or global variable is affected by more than one section defining feature

当同一个函数/变量被赋予多个段特性（__attribute__((section)) 与 #pragma clang section）时，开启该选项后编译器给出警告。

// section_feature.c（按 userguide 示例）
#pragma clang section bss=".test1"
__attribute__((section(".test11"))) int test1;      // 警告
#pragma clang section bss=""
#pragma clang section text=".test2"
__attribute__((section(".test22"))) void test2(void){}  // 警告
#pragma clang section text=""
#pragma clang section bss=".test3"
#pragma clang section bss=".test33" int test3;       // 警告（pragma 覆盖）
#pragma clang section bss=""
clang -Wsection-feature -c section_feature.c  ->  4 条警告，例如：
  warning: .test11 uses more than one section feature [-Wsection-feature]
  warning: '#pragma clang section' overrides previous active section
clang -Wno-section-feature ...  ->  无警告（可抑制）
clang（默认，不带选项）            ->  无警告（选项默认关闭）

实测附加行为：由于 -ffunction-sections/-fdata-sections 默认开启，单独的 __attribute__((section)) 也会被判定为"超过一个 section 特性"而告警（即使加 -fno-function-sections -fno-data-sections 亦然），属本工具链实现行为，使用该选项时需注意。

测试结果：通过。

[CCRM-150] Add option -fno-zero-initialized-in-bss-gcc as a GCC compatible variant of -fno-zero-initialized-in-bss

默认情况下全局/静态变量初始化为 0 或不初始化都放入 .bss。GCC 中 -fno-zero-initialized-in-bss 用于区分显式 =0 与未初始化变量；为保证 GCC 兼容性，HighTec 新增 -fno-zero-initialized-in-bss-gcc 变体（仅把显式 =0 的变量移出 .bss，隐式未初始化变量仍留在 .bss）。

// bss_test.c
int implicit_zero;      // 隐式零初始化
int explicit_zero = 0;  // 显式零初始化
int nonzero = 7;        // 非零对照
llvm-nm -S obj\bss_*.o  (B=\.bss 节，D=\.data 节)
  变量           默认      -fno-zero-init-in-bss   -fno-zero-init-in-bss-gcc
  implicit_zero   B        D                       B
  explicit_zero   B        D                       D
  nonzero         D        D                       D

三组行为与 userguide 表格完全一致（-gcc 变体仅把显式 =0 移到 .data，匹配 GCC 行为）。

测试结果：通过。

测试总结

  • 11.0.0 新增特性中，本机可测试项（LLVM 21.1.8、RLM 18、Picolibc 1.8.11、默认独立节、默认 GC、-Wsection-feature、-fno-zero-initialized-in-bss-gcc、去除 MSVC2015 依赖、端到端冒烟、累积特性抽测）全部测试通过。
  • 默认开启 -ffunction-sections/-fdata-sections/--gc-sections 属行为变更，会对用户工程有影响：链接脚本需匹配 *(.text*) 等通配规则；自定义段问题可用 -fno-pragma-function-sections -fno-pragma-data-sections 处理。
  • 本机无法测试项：CCRM-10（ARM64 Linux 主机支持，需对应平台实测）、CCRM-78（SPDX 3.0.1 FOSS 报告，未随安装包落盘，需官方门户获取）、CCRM-85 / TCTRIC-1348 / TCTRIC-1349（安装器改进，需交互运行安装器验证）。
