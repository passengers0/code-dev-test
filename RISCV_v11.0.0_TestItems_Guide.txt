        C:\HighTec\toolchains\riscv\v11.0.0\bin\llvm-nm.exe build\gc_default_clang.elf

        setx PATH "$env:PATH;C:\HighTec\toolchains\riscv\v11.0.0\bin"

 T2  CCRM-123  升级到 RLM 18                                  [无专用测试代码]
--------------------------------------------------------------------------
 说明: 验证内嵌 RLM 客户端版本为 18，且许可证检出机制正常。
       使用 src\sections_default.c 作为任意可编译输入即可。
 前置条件:
   - RLM_LICENSE 已指向 C:\HighTec\licenses（本机系统环境变量已配置；
     当前 PowerShell 会话可显式设置 $env:RLM_LICENSE="C:\HighTec\licenses"）
   - 许可证文件 riscv_llvm_acc12281_lic_nodelocked_sen16164.lic 存在
   - 任意可编译 .c 输入（本项使用 src\sections_default.c）
 原理说明(关键取证手段):
   工具链自身没有 "--version 打印 RLM 版本" 的入口。RLM 客户端支持环境变量
   RLM_DIAGNOSTICS：设置非零值后，每次许可证初始化(rlm_init)会在【当前工作
   目录】输出数字命名的诊断文件（本机实测生成 "2"、"3" 两个文件），文件头即
   打印内嵌 RLM 客户端版本号。这是读取内嵌 RLM 版本最直接的方法。
 步骤1(许可证检出机制, 正向):
   直接编译一次，验证许可证检出成功：
     cd C:\work\code\riscv11_test
     %TC%\bin\clang.exe -target riscv32-unknown-elf -march=rv32imac `
         -mabi=ilp32 -c src\sections_default.c -o obj\tl.o
     echo %ERRORLEVEL%          (PowerShell: echo $LASTEXITCODE)
   通过标准: 退出码 0（riscv-llvm 许可证检出成功）。
 步骤2(设置诊断开关并触发):
   PowerShell 下：
     $env:RLM_LICENSE="C:\HighTec\licenses"
     $env:RLM_DIAGNOSTICS="2"
     %TC%\bin\clang.exe -target riscv32-unknown-elf -march=rv32imac `
         -mabi=ilp32 -c src\sections_default.c -o obj\tl2.o
   (PowerShell 等价: & "$env:TC\bin\clang.exe" ... )
   编译成功后，当前工作目录 C:\work\code\riscv11_test 下出现数字命名的
   诊断文件（本机为 "2" 与 "3"）。文件以 "RLM Diagnostics at ..." 开头。
 步骤3(读取内嵌 RLM 版本号, 关键):
   PowerShell 下读取诊断文件头部：
     Get-Content .\2 -TotalCount 6
   预期输出:
     RLM Diagnostics at 09/04/2026 14:11
         RLM version: 18.0BL1
         RLM platform: x64_w4
         OS version: 6.2
         ISV name: hightec-rt
         Hostname: hightec-071
   其中 "RLM version: 18.0BL1" 即内嵌 RLM 客户端版本 → 确认 RLM 18。
 步骤4(查看 riscv-llvm 许可证检出状态, 同一文件):
     Select-String -Path .\2 -Pattern "riscv-llvm"
   预期输出:
     In license file C:\HighTec\licenses\riscv_llvm_acc12281_lic_nodelocked_sen16164.lic
           (no server)
         riscv-llvm v2026.12 OK
   含义: 节点锁定(无 server)许可证，riscv-llvm v2026.12 版本可正常检出(OK)。
 诊断文件关键字段解读:
     字段                                    含义
     RLM version: 18.0BL1                  内嵌 RLM 客户端版本(本测试目标)
     RLM platform: x64_w4                  RLM 平台 = Windows 64 位
     OS version: 6.2                       Windows 内核版本 6.2
     ISV name: hightec-rt                  软件供应商 ID
     Hostname / User / Working directory   主机名、用户名、触发时工作目录
                                           (即诊断文件生成位置)
     RLM hostid list                       节点锁定绑定的主机特征
                                           (uuid/网卡MAC/磁盘序列号等)
     License files                         RLM_LICENSE 目录下扫描到的全部 .lic
     In license file ... .lic              逐文件列出特性检出状态:
       riscv-llvm v2026.12 OK               OK=可检出; error:-3/-2=不可检出
 通过标准: 诊断文件头部打印 "RLM version: 18.0BL1"，且
           "riscv-llvm v2026.12 OK"。
 负向验证(可选, 许可证机制):
   将 RLM_LICENSE 指向不存在的路径后编译：
     $env:RLM_LICENSE="C:\nonexistent"
     %TC%\bin\clang.exe -target riscv32-unknown-elf -march=rv32imac `
         -mabi=ilp32 -c src\sections_default.c -o obj\tl3.o
   预期 stderr: Error checking out 'riscv-llvm' license:
                Can't read license data (-102)
   -102 = 读取不到许可证数据(通常因 RLM_LICENSE 路径无效)，与过期/无权限
   (-3 等)不同；检出机制正确响应错误。
 清理与注意事项:
   - 诊断文件生成在【当前工作目录】且为数字命名(本机 "2"/"3")，非固定文件名，
     需按目录内"新增文件"识别；验证后建议归档或删除：
        Move-Item .\2 build\rlm_diagnostics.txt          (归档)
        Move-Item .\3 build\rlm_diagnostics2.txt
     (本机已归档，见 build\rlm_diagnostics.txt / rlm_diagnostics2.txt)
   - 恢复环境变量，避免后续每次编译都生成诊断文件：
        Remove-Item Env:RLM_DIAGNOSTICS
        $env:RLM_LICENSE="C:\HighTec\licenses"
   - 诊断文件含主机特征(hostid)等敏感信息，归档/交付时注意脱敏。

 T5  CCRM-176  函数与静态分配变量默认生成 unique sections    [src\sections_default.c]
--------------------------------------------------------------------------
 说明: 验证不添加 -ffunction-sections/-fdata-sections 时，默认即生成
       .text.<func> / .data.<var> / .bss.<var> / .rodata.<var> 独立节。
 测试代码内容:
   src\sections_default.c
     - int global_init = 5;        /* 预期 .data.global_init  */
     - static int static_init = 6; /* 预期 .data.static_init  */
     - int global_zero;            /* 预期 .bss.global_zero   */
     - static int static_zero;     /* 预期 .bss.static_zero   */
     - func_a / helper(static) / func_b  /* 预期 .text.func_a / .text.helper / .text.func_b */
   src\rodata_test.c（补充常量用例）
     - const int table[4]; const char msg[];  /* 预期 .rodata.table / .rodata.msg */
 编译命令（注意: 不能加 -ffunction-sections / -fdata-sections）:
   %TC%\bin\clang.exe -target riscv32-unknown-elf -march=rv32imac -mabi=ilp32 `
       -c src\sections_default.c -o obj\sections_default.o
   %TC%\bin\clang.exe -target riscv32-unknown-elf -march=rv32imac -mabi=ilp32 `
       -c src\rodata_test.c -o obj\rodata_test.o
 验证命令:
   %TC%\bin\llvm-objdump.exe -h obj\sections_default.o
   %TC%\bin\llvm-objdump.exe -h obj\rodata_test.o
 预期输出: 节列表包含 .text.func_a / .text.func_b / .text.helper /
           .data.global_init / .data.static_init / .bss.global_zero /
           .bss.static_zero / .rodata.table / .rodata.msg
 附加确认(驱动默认参数):
   %TC%\bin\clang.exe -target riscv32-unknown-elf -march=rv32imac -mabi=ilp32 `
       -### -c src\sections_default.c
   输出 cc1 参数中应包含 "-ffunction-sections" "-fdata-sections"
   "-fpragma-function-sections" "-fpragma-data-sections"。
 通过标准: 默认编译即出现上述独立节，且驱动默认传递 -f/-fdata-sections。

 T6  CCRM-176  lld 默认启用未引用节 GC                       [src\gc_default.c + .ld]
--------------------------------------------------------------------------
 说明: 验证经 clang 驱动链接时默认开启 --gc-sections，未引用函数/变量被回收。
 测试代码内容:
   src\gc_default.c
     - used_global / used_func   /* 被 _start 引用，必须保留 */
     - unused_global / unused_func /* 不被引用，默认应被回收 */
     - void _start(void){ used_func(1); for(;;); }  /* 入口 */
   src\gc_default.ld             /* 最小链接脚本, ENTRY(_start), RAM@0x80000000 */
 步骤1 编译:
   %TC%\bin\clang.exe -target riscv32-unknown-elf -march=rv32imac -mabi=ilp32 `
       -c src\gc_default.c -o obj\gc_default.o
 步骤2 经 clang 驱动链接(默认, 应触发 GC):
   %TC%\bin\clang.exe -target riscv32-unknown-elf -march=rv32imac -mabi=ilp32 `
       -nostdlib -T src\gc_default.ld obj\gc_default.o `
       -o build\gc_default_clang.elf
 验证:   %TC%\bin\llvm-nm.exe build\gc_default_clang.elf
 预期:   仅 _start / used_func / used_global；unused_func / unused_global 被回收。
 附加确认(驱动默认传 --gc-sections):
   ... 上述链接命令加 -###，可见 ld.lld 参数含 "--gc-sections"。
 对照(直接 ld.lld):
   无 GC: %TC%\bin\ld.lld.exe -m elf32lriscv -T src\gc_default.ld `
             obj\gc_default.o -o build\gc_default_default.elf
          -> unused_func / unused_global 保留(无 GC)
   显式 GC: %TC%\bin\ld.lld.exe -m elf32lriscv --gc-sections `
             -T src\gc_default.ld obj\gc_default.o `
             -o build\gc_default_explicit.elf
          -> 同 clang 驱动，被回收
 通过标准: 经 clang 驱动默认链接时未引用节被回收；显式 --gc-sections 一致；
          裸 ld.lld 不带该选项时保留（符合 lld 原生语义）。

 T7  CCRM-110  新增 -Wsection-feature 警告选项               [src\section_feature.c]
--------------------------------------------------------------------------
 说明: 验证警告选项能识别、能触发、能抑制。
 测试代码内容:
   src\section_feature.c（按 userguide 示例）
     - #pragma clang section bss=".test1" + __attribute__((section(".test11"))) int test1;
       -> 预期警告 (attribute 覆盖 pragma)
     - #pragma clang section text=".test2" + attribute test2()
       -> 预期警告
     - #pragma clang section bss=".test3" 后紧跟 bss=".test33"
       -> 预期警告 (pragma 覆盖前一 pragma)
     - __attribute__((section(".single"))) int ok_single;
       -> 本工具链实测也告警(因默认 unique-sections 使 attribute 计为多特性)
     - 纯 pragma(ok_pragma) / 无任何 section 特性的变量 -> 不告警
   src\section_feature_min.c（最小触发用例，单独 attribute 是否告警）
 编译命令（三组对照，stderr 重定向到文件以便核对）:
   (1) -Wsection-feature
       %TC%\bin\clang.exe -target riscv32-unknown-elf -march=rv32imac -mabi=ilp32 `
           -Wsection-feature -c src\section_feature.c -o obj\section_feature.o
       -> 预期 4 条 warning:  "... uses more than one section feature
          [-Wsection-feature]" 及 "'#pragma clang section' overrides previous
          active section"
   (2) -Wno-section-feature
       ... -Wno-section-feature ... -> 预期 0 条警告
   (3) 默认(不带选项) -> 预期 0 条警告(该选项默认关闭)
 通过标准: -Wsection-feature 触发警告、-Wno- 与默认均抑制；选项名被 clang 接受。

 T8  CCRM-150  新增 -fno-zero-initialized-in-bss-gcc          [src\bss_test.c]
--------------------------------------------------------------------------
 说明: 验证 GCC 兼容变体：仅显式 =0 的全局变量被移出 .bss，隐式零初始化

 测试代码内容:
   src\bss_test.c
     - int implicit_zero;   /* 隐式零初始化 */

     - int nonzero = 7;     /* 非零，恒 .data 对照 */
 三组编译命令:
   (1) 默认
       %TC%\bin\clang.exe -target riscv32-unknown-elf -march=rv32imac -mabi=ilp32 `
           -c src\bss_test.c -o obj\bss_default.o
   (2) -fno-zero-initialized-in-bss
       ... -fno-zero-initialized-in-bss -c src\bss_test.c -o obj\bss_no-zero-bss.o
   (3) -fno-zero-initialized-in-bss-gcc
       ... -fno-zero-initialized-in-bss-gcc -c src\bss_test.c `
           -o obj\bss_no-zero-bss-gcc.o
 验证命令: %TC%\bin\llvm-nm.exe -S obj\bss_*.o
 预期结果(B=bss节, D=data节):
   变量          默认      -fno-zero-init-in-bss    -fno-zero-init-in-bss-gcc
   implicit_zero  B        D                       B
   explicit_zero  B        D                       D
   nonzero        D        D                       D
 通过标准: 三组符号归属与上表一致（-gcc 变体仅把显式 =0 移到 .data）。
